# prompt-coach

[English](README.md) | 简体中文

在 **Pi** 和 **Oh My Pi（OMP）** 中，把粗略的编码想法整理成清楚、可执行的提示词。先澄清需求、查阅相关证据，再展示完整成稿，由你选择是否在当前会话执行。

## 安装

```bash
# Pi
pi install npm:@sonsong/prompt-coach

# OMP
omp plugin install @sonsong/prompt-coach
```

重启宿主，或使用宿主支持的扩展重载功能。验证版本为 **Pi 0.87.0** 和 **OMP 18.4.2**。两个宿主共用一个 JavaScript 扩展和一份引导规则。引导复用宿主已有模型和上下文，无须单独配置模型账号或 API Key。

## 使用

在空闲会话中启动：

```text
/prompt-coach 登录页偶尔失败，帮我整理一个有用的排错任务。
```

插件优先利用当前对话，必要时读取或搜索相关项目文件。每轮最多追问 1—3 个关键问题，有内置提问工具时优先使用。完整需求直接进入成稿。随时可以说“**直接生成**”“**跳过**”或提出修订；未回答的问题会保留为明确的未知项。

例如，模糊的排错需求会整理为包含复现步骤、预期与实际行为、证据、失败尝试、范围和验收条件的提示词。简单且完整的需求仍保持简短。

## 工具为什么有价值

编码代理只能根据当前上下文中明确的信息行动。需求模糊时，模型需要猜测目标、相关证据、允许的范围和完成标准，容易造成反复追问、找错文件、改动范围过大，以及难以验收的结果。

`prompt-coach` 会在任务开始前把粗略想法整理成一份紧凑的交接提示词：突出目标、证据、约束和完成标准，保留有价值的失败尝试，在未知信息变成错误假设前把它们暴露出来，并让你确认最终提交的完整提示词。引导阶段保持只读，完善提示词不会改动项目文件。对于排错、实现、审查和方案设计等需要在对话中保留多项约束的任务，这能显著减少沟通往返和方向偏差；简单且完整的需求仍然保持简短。

| 命令 | 行为 |
| --- | --- |
| `/prompt-coach <想法或提示词>` | 开始引导，或修订当前需求。 |
| `/prompt-coach` | 提示输入想法；已有待确认成稿时，重新打开选择框。 |
| `/prompt-coach cancel` | 结束引导并恢复原工具配置，不启动任务。 |

追问、改进说明和确认界面跟随用户语言，支持英文与简体中文，没有语言上下文时默认英文。可以说“请切换到英文”或“continue in Chinese”切换，也可以单独指定成稿语言。

## 基于《提示词工程.md》的原则

共享的引导规则把项目笔记中的五条原则落实成可重复的流程：

1. **少而准** —— 保留高相关背景和有价值的失败尝试，删除重复信息与无关噪声。
2. **突出重点** —— 按背景、证据、任务、约束和输出组织提示词，让最重要的限制靠近任务和完成标准。
3. **先事实后判断** —— 在判断原因或提出方案前，区分已确认事实、猜测和缺失证据。
4. **具体化要求** —— 把“认真分析”这类模糊表达改成具体文件、检查方向、示例、边界和预期结果。
5. **明确完成标准** —— 写清范围、交付物和验收条件，避免任务在执行过程中悄悄扩大。

这些做法把笔记中的模型概念转成可使用的提示词结构：用相关上下文引导注意力，用清晰位置突出重点，用事实建立可靠的理解状态，用具体示例减少语义歧义，再用明确约束缩小可能的输出方向。引导只追问缺失信息，不要求每个需求都套用固定模板。

## 确认与执行

扩展先展示可复制的完整提示词和最多三条改进说明，再打开宿主原生选择框。

| 选择 | 结果 |
| --- | --- |
| **执行** | 结束引导，恢复原工具配置，把展示的成稿提交到当前会话一次。继续遵守宿主现有权限和计划模式规则。 |
| **继续完善** | 保持只读，等待补充意见。修订后的成稿需要重新确认。这是默认选项。 |
| **仅保留提示词** | 将成稿留在对话中，结束引导，不启动任务。 |
| **关闭弹窗／中断** | 保持只读和待确认状态。用 `/prompt-coach` 重新打开选择框。 |

输入新的消息会使旧成稿的确认失效。内部工具 `prompt_coach_finish` 只能提交成稿，不能授权或启动执行。没有交互界面时，扩展只展示成稿，不会自动执行。

## 只读边界与会话恢复

引导或等待确认期间，只开放经核实的内置读取、搜索、目录浏览、提问工具，以及插件自己的成稿工具。编辑、写入、Shell、脚本、子代理和未知工具调用均被拦截；第三方工具即使使用允许的工具名称也不会放行。直接输入的 Shell 命令和 OMP 的直接 Python 命令也会在引导期间被拦截。

阶段、成稿和原活动工具配置保存在宿主会话记录中。重载、恢复和分支切换按当前分支恢复状态，不重放执行请求。通过 `cancel`、“执行”或“仅保留提示词”退出引导。插件不会在项目中创建成稿文件。

这个限制覆盖扩展已加载时的宿主工具和直接命令入口，不是针对其他进程或其他扩展自身代码的操作系统沙箱。被扩展覆盖的工具不会进入只读白名单。请使用可信扩展，并避免在引导期间切换宿主模式。

## 引导原则

共享的[引导规则](coaching.md)落实五条原则：

1. 保留相关背景和有价值的失败尝试，压缩重复内容。
2. 突出任务和关键限制，避免重点埋在长文中。
3. 区分已确认事实、猜测和缺失证据。
4. 将模糊表达转为具体要求或示例。
5. 明确范围、交付物和验收标准，不擅自扩大任务。

根据需求实现、排错、审查或方案设计调整关注点。追问由信息缺口决定，无须填写固定问卷。
